第一课 · 第 10 阶段：Production ML：监控、反馈与持续学习

把 ProcurementML 从“离线高分模型”升级为能被持续监控、反馈、纠错、安全升级和回滚的生产机器学习系统。

Production MLMonitoringDriftHuman-in-the-LoopRetrainingShadow/Canary

一、第 10 阶段总地图：上线不是训练完成，而是真实考试开始

Train → Deploy → Observe → Fail → Feedback → Retrain → Redeploy ↺

Offline Test 只是我们对现实的模拟，Production 面对的才是真实 P_real(X,Y)。因此生产模型必须被持续观察、反馈、纠错和重新训练。

核心心智模型 ①：上线不是终点，而是模型第一次进入真正考试。

Offline Performance ≠ Production Performance。

二、Training-Serving Skew：模型没变，输入管线变了也会崩

训练时 PDF 经过高质量解析，线上却由另一套 Parser 丢失表格、标题和上下文，那么 X_train ≠ X_serve。

训练：PDF → 高质量文本抽取 → 正确分段 → 模型
线上：PDF → 另一解析器 → 表格丢失/标题错位 → 模型

这类问题常被误诊为“LLM 不够聪明”，实际根因可能是 Document Parsing。

核心心智模型 ②：生产质量由整个系统共同决定。

Quality ≈ Data Pipeline × Model × Retrieval × Rules × Serving。

三、Production Monitoring 的五层结构

System + Data + Model + Business + Human Feedback
System

成功率、P95/P99 延迟、GPU/显存、吞吐、错误率、队列。

Data

文档类型、Token 长度、行业、地区、采购方式、OCR/解析失败率。

Model

风险报警率、风险分数、High Risk、拒答率、低置信度比例。

Business

专家接受率、漏报抽检、建议采用率、法规引用正确率。

四、线上 Recall 为什么难：必须监控模型“没说出来什么”

Precision 可以检查模型报出来的风险；Recall 需要知道模型没报警的“正常案例”里还藏着多少真实风险。

每周从模型判为“无风险”的案例中随机抽样，让专家重新审查，估计 FN。

例如从 1,000 条未报警案例中抽 100 条，专家发现 5 个漏报，这就是线上 Recall 健康度的重要信号。

核心心智模型 ③：风险模型不能只监控它说了什么，还要主动寻找沉默的错误。

否则系统可能表面 Precision 很高，却漏掉大量风险。

五、Human Feedback：线上用户正在产生最高价值的数据

专家对模型输出可以 Accept / Edit / Reject / Add Missed Risk，于是天然得到 (X, Ŷ, Y) 结构。

Raw Feedback
   ↓
Quality Check
   ↓
Expert Review
   ↓
Confirmed Feedback
   ↓
Training Data

反馈不能直接视为 Ground Truth；误操作、非专家意见和标准不一致必须先过滤。

核心心智模型 ④：专家不是模型失败后的补丁，而是学习系统的一部分。

专家同时负责兜底、纠错、产出困难样本、定义规则和形成下一轮训练数据。

六、哪些线上案例最值得专家复核？

  1. 低置信度 / 决策边界附近
  2. 高业务风险、高错误代价
  3. OOD / 新行业 / 新地区
  4. LLM 与 Rule Engine 冲突
  5. 新旧模型意见不一致
  6. 高置信度错误——最有价值的错误案例

这就是第 6 阶段 Active Learning 与生产反馈系统真正连接起来的地方。

七、Drift Monitoring：线上世界会变，模型不会自动知道

Data Drift

P(X) 变化：例如医疗项目从 8% 涨到 45%。

Label Drift

P(Y) 变化：风险条款总体比例因治理变化而下降。

Concept Drift

P(Y|X) 变化：新法规、新政策、新监管口径改变同类事实的结论。

Concept Drift 对政府采购尤其重要，因为规则具有时间有效性和适用范围。

八、知识更新与模型更新必须分成两个周期

新法规/政策
   ↓
Knowledge Update：RAG / Rule Engine 先更新 → 可快速生效

积累新案例/专家纠错
   ↓
Model Update：Dataset vNext → Retrain → Evaluation → Deploy

变化快的法规知识更适合进入 RAG / Rules；相对稳定的领域语言、工作方式和专家推理模式才更适合进入模型参数。

通常：Knowledge Update Frequency > Model Parameter Update Frequency

九、什么时候应该 Retrain？建立明确 Trigger，而不是“想起来就训”

Trigger动作
Performance DropRecall / High-Risk Recall 连续低于门槛，先调查再决定重训
明显 Drift先对漂移 Slice 重新评估，确认能力缺口
Enough New Data积累足够专家纠错和新领域数据后重训
Major Rule Change先更新 RAG/Rules，再准备新规则下标注数据
New Business Domain建立新域测试集 → 评估 → 补数据 → 训练

十、安全部署：离线更好 ≠ 直接替换生产模型

Shadow Deployment

新模型接收真实流量但不把答案展示给用户，先比较真实输入上的性能、延迟、OOD 与输出分布。

Canary Deployment

先让 5% 流量使用 V1.1，再逐步 20% → 50% → 100%。

A/B Test

在两个安全候选之间比较专家接受率、审查时间等真实业务指标。

Rollback

新版本出现重大回归，应能快速退回 Model Registry 中上一稳定版本。

核心心智模型 ⑤：每个新模型都要假定“可能退化”。

Evaluate → Shadow → Canary → Monitor → Promote，同时始终准备 Rollback。

十一、Continual Learning 与灾难性遗忘：学新能力也可能毁掉旧能力

如果只用大量医疗数据继续训练，医疗 Recall 可能上涨，但资格条件从 96% 掉到 78%。这叫 Catastrophic Forgetting。

Retraining Dataset = New Data + Hard Errors + Representative Replay Data

目标是 Learn New + Preserve Old，所以新模型必须做 Regression Evaluation。

十二、一个真正“活着”的模型健康仪表盘

System Health

Request/min、Latency、Error Rate、GPU。

Data Health

行业/地区/Token 分布、Parser 成功率、OOD 比例。

Model Health

Risk Rate、Confidence、Abstention、Precision/Recall 抽检。

Knowledge Health

法规检索命中率、有效法规比例、过期引用率。

Human Feedback

接受率、修改率、驳回率、漏报补充数。

Drift

Data / Label / Concept Drift 信号。

十三、Inference Lineage：线上一个结论必须能追踪“是谁共同产生的”

Request ID
 ↓ Document Version
 ↓ Parser Version
 ↓ Model Version
 ↓ Prompt Version
 ↓ RAG Query / Retrieved Laws
 ↓ Rule Engine Result
 ↓ Model Output
 ↓ Final Decision

LLM 系统里 Prompt、Retriever、Embedding、Reranker、Knowledge Base 都会改变结果，因此生产版本最终应该是一个 System Version，而不仅是“模型 v1.3”。

十四、模型指标不是终点：最终要映射到 Workflow 与 Business Outcome

Model Metric → Workflow Metric → Business Outcome

真正业务指标可以包括：每份文件审查时间、Critical Miss Rate、Expert Acceptance Rate、Revision Rate、Expert Hours Saved、Time to First Useful Finding。

Recall 提高但专家审查时间反而增加、误报疲劳严重，产品未必成功。

十五、反馈循环会反过来改变未来数据

AI 提示注册资本限制风险 → 采购人逐渐不再写这类条款 → 未来 P(X) 变化。模型不是只观察现实，它也可能改变现实。

Production → Prediction → Expert Review → Feedback
       ↑                               ↓
       └── Registry ← Evaluate ← Train ← Error Bank / Dataset vNext

十六、第 10 阶段的 5 个专家核心心智模型

① 上线才是真实考试

Test Set 只是现实模拟，Production 才是真实分布。

② 系统而非单模型决定质量

Parser、RAG、Rules、Serving 都可能造成错误。

③ 必须监控沉默错误

风险系统要抽检模型判正常的案例，寻找 FN。

④ 专家是学习闭环的一部分

Human Feedback 应进入经过质量控制的数据回流。

⑤ 新模型默认可能退化

Shadow、Canary、Regression Test 与 Rollback 必不可少。

模型不是“训练出来的产品”，而是一个需要持续观察、纠错和重新学习的动态系统。
