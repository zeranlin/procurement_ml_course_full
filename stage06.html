第一课 · 第 6 阶段：数据分布、采样与“数据即模型”

Distribution、Imbalance、Hard Examples、Curriculum、Active Learning

DistributionImbalanceHard ExamplesCurriculumActive Learning

一、Data Distribution：模型不是在学“整个政府采购”，而是在学你给它看的那部分世界

假设训练数据中风险类型分布：

资格条件 40%
技术参数 25%
评分标准 15%
商务条件 10%
合同条款 5%
程序问题 5%

这就是训练分布 P_train(X,Y)。未来部署环境有自己的 P_real(X,Y)。

理想：P_train(X,Y) ≈ P_real(X,Y)
Training Distribution 定义了模型经验边界。

因此建设数据集时，要按采购对象、行业、采购方式、地区、风险类型、风险等级、难度等维度做 Data Slicing。

二、Distribution Shift：模型没有一定“坏掉”，可能只是进入了陌生世界

例如：

训练：IT 项目占 80%
部署：医疗设备占 60%

这就是 Train / Deploy 分布不一致。即使总体测试不错，也可能在医疗场景明显掉点。

维度政府采购示例
采购对象货物 / 服务 / 工程
行业IT / 医疗 / 教育 / 物业 / 工程 / 咨询
采购方式公开招标 / 磋商 / 谈判 / 询价 / 单一来源
地区中央 / 省 / 市 / 县 / 不同省份
风险类型资格 / 参数 / 评分 / 商务 / 合同 / 程序
难度明显 / 普通 / 边界 / 争议

三、Class Imbalance：样本频率本身就是一种“隐形奖励函数”

假设：

无风险：95,000
有风险：5,000

模型很容易学会大多数时候预测“无风险”。训练策略可以包括：

  • Oversampling：提高少数类出现频率。
  • Undersampling：减少多数类样本。
  • Class Weight：不改变数量，但提高少数类错误在 Loss 中的权重。
  • Cost-sensitive Learning：按业务代价让某类错误更贵。
Loss = w₁·L(risk) + w₀·L(normal)
样本频率 = Implicit Weight。

一个模式出现 100 万次，另一个只出现 1000 次，即使 Loss 形式相同，前者对参数的累计影响也会更强。

四、Hard Positive / Hard Negative：真正推动能力边界的是“模型最容易错的样本”

Hard Negative：看起来像风险，其实不一定是

项目需要在本市提供 2 小时应急服务，
但不要求供应商提前设立本地机构，
可通过驻场、合作服务等方式满足。

如果模型学的是“出现本市 → 风险”，它会误报。这类案例专门打掉错误捷径。

Hard Positive：看起来很合理，实际可能存在风险

“为确保服务质量，供应商须具有连续十年以上同类项目经验。”

措辞有合理化包装，但仍要判断 10 年要求是否必要、与履约能力是否合理相关、是否不当限制竞争。

简单样本教模型“表面规则”；困难样本决定它能不能画准真正的决策边界。

五、Hard Example Mining 与 Error Bank：让模型自己告诉我们“下一批最该标什么”

Hard Negative Mining

当前模型扫描大量数据
→ 找出高置信度判“风险”的案例
→ 专家确认其实正常
→ 加入 Hard Negative 数据集
→ 下一轮训练专门修复

Hard Positive Mining

如果模型对真实风险给出 p<0.2，说明它非常自信地错了。这类 High-Confidence Wrong 案例价值很高，因为它暴露系统性认知盲区。

Error Bank（错误案例库）建议字段：
model_version
prediction
confidence
expert_label
error_type
root_cause
risk_category
jurisdiction
time
evidence
whether_retrained
Model → Error → Expert Correction → New Data → Better Model → 再发现新错误

六、Duplicate 与 Long Tail：10 万条不一定有 10 万条有效信息

重复数据

如果“注册资本不得低于 X 万元”换数字、项目名重复 2 万次，它会在训练中被赋予过强影响。

Raw Count ≠ Effective Information

去重可分：

  • Exact Dedup：完全相同
  • Near Dedup：文字高度近似
  • Semantic Dedup：语义高度重复

Long Tail：低频不等于不重要

资格条件可能 30,000 条，特殊政策问题只有 100 条。模型会自然偏向高频类别，而低频案例往往更复杂。可以通过专项采集、Oversampling、Class Weight、RAG、Rules 或专项模型处理。

七、Curriculum Learning 与 Contrastive Pair：Dataset 是课程，不是仓库

课程学习

Level 1：明显案例
→ Level 2：普通上下文案例
→ Level 3：对比案例
→ Level 4：边界案例
→ Level 5：争议案例 / 不确定性

这叫 Curriculum Learning：像教学生一样设计学习顺序。

Contrastive Pair

A

供应商必须在本市设立分公司。

标签：高风险。

B

中标供应商应在合同履行期提供本地化现场服务，但不限制注册地或机构设立方式。

标签：结合项目需要判断，未必构成限制。

把 A/B 放在一起，比把 A 重复 100 次更能迫使模型学习“真正差异”。

八、Active Learning：专家时间有限，下一条最值得标什么？

假设有 100 万条未标注采购案例，但专家只能标 1 万条。随机抽不一定最优，可以让当前模型先跑，优先挑：

  • 模型最犹豫：p≈0.5
  • 多个模型意见分歧
  • 模型与规则引擎冲突
  • 高置信度但人工抽检发现错误
  • 稀缺/长尾业务类别
真正昂贵的往往不是 GPU，而是高质量专家时间。目标应是：每 1 小时专家标注，产生最大的模型能力提升。

九、Data Quality、Temporal Metadata 与 Leakage：专业领域数据必须带“时间和适用范围”

一条高质量政府采购训练数据至少要检查：

  1. 输入是否完整，有没有缺上下文？
  2. 标签是否正确、专家标准是否一致？
  3. 法规依据是否真实、有效、适用？
  4. 地区、时间、项目类型是否记录？
  5. 是否重复？
  6. 难度是否标注？
  7. 是否存在答案/未来信息泄漏？

Temporal Metadata

{
  effective_date,
  expired_date,
  case_date,
  jurisdiction,
  source_type,
  legal_status
}

政府采购规则会变化。如果把不同时期相互冲突的规则混在一起而没有时间信息，模型可能把失效规则当成当前规则。

Label / Future Leakage

任务是审原始采购文件，却把“财政部门认定该条款构成不合理限制”放进输入；或要预测是否投诉，却给了后续投诉处理决定——都会让模型“作弊”。

十、ProcurementLM 数据质量金字塔：真正的护城河在哪里？

层级内容单位价值
L1 原始数据法规、公告、采购文件、案例基础
L2 清洗数据去乱码、解析、去重↑
L3 结构化项目、地区、时间、条款、风险类型↑
L4 专家标注标签、依据、理由、建议高
L5 困难数据Hard Positive / Negative / Contrastive更高
L6 错误闭环模型真实犯错 + 专家纠正最高之一

公开原始数据别人也能抓，真正难复制的是 L4 + L5 + L6：专家标注、困难案例和真实错误反馈。

十一、本阶段 5 个专家核心心智模型

  1. 训练数据就是模型看到的世界：Train Distribution 定义经验边界。
  2. 样本频率就是隐形权重：高频数据对参数影响更大。
  3. 困难样本决定能力边界：模型最容易错的地方最有训练价值。
  4. 高置信度错误是宝藏：它暴露最深的错误规律。
  5. Dataset 是课程，不是仓库：要主动设计顺序、对比、反例与边界样本。
不要只问“我有多少数据”，要问“这些数据正在把模型训练成什么样的人”。

十二、深化理解：如何判断“下一条数据值不值得标”

1. Dataset A 与 Dataset B：数量不是唯一答案

Dataset ADataset B
总量100,00030,000
普通正常90%30%
明显风险8%25%
Hard Negative很少20%
Hard Positive很少15%
边界案例2%10%

专家不会因为 100,000 > 30,000 就自动选 A，而会比较：

Coverage + Balance + Difficulty + Label Quality + Deployment Match

2. Data 的边际价值会下降

如果模型已经对“明显注册资本限制”达到 99.9% 正确率，再加 10 万条同类句子收益很低；增加 5000 条模型经常犯错的边界样本，可能更有效。

专家问的不是“还能抓多少数据”，而是“下一条什么数据最值得花专家时间标？”

3. Active Learning 的优先级队列

优先级 A：高置信度错误（最值得查）
优先级 B：多个模型强烈分歧
优先级 C：模型与规则引擎冲突
优先级 D：p≈0.5 的高不确定样本
优先级 E：稀缺行业/地区/风险类型
优先级 F：随机样本，用于保持总体分布代表性

4. 时间为什么不仅是 Metadata，也可能是 Input X？

如果同一条款在不同政策时期、地区或采购制度背景下适用规则不同，那么：

X = [条款, 上下文, 项目类型, 地区, 时间, 适用规则]

模型只有知道“什么时候、在哪里”，才能更可靠地使用正确的规则。

5. 数据课程设计的最终目标

基础样本帮助模型学基本模式；Hard/Contrastive 样本修正决策边界；长尾样本扩展覆盖；错误案例修复真实盲区；时间与地区元数据让知识有适用边界。

你不是在维护一个数据仓库，而是在持续设计 ProcurementLM 的“教育体系”。
