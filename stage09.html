第一课 · 第 9 阶段：工程化与可复现性

从“会训练”进入“能管理训练”：让数据、代码、配置、环境、Checkpoint、评测与生产模型形成完整证据链。

MLOpsVersioningReproducibilityExperiment TrackingModel RegistryLineage

一、第 9 阶段总地图：把一次好实验变成可复现的模型资产

今天训练出的 ProcurementML V0.1，三个月后能不能准确知道它由什么数据、代码、参数和环境产生？
Dataset Version → Code Version → Config → Experiment → Checkpoint → Evaluation → Model Registry → Deployment

如果只剩一个 model.safetensors，而没人知道数据版本、代码 commit、阈值和 Gold Set，那么这个模型很难被称为可管理的专业资产。

二、模型不是一个权重文件，而是一整套“训练状态”

Model Artifact = Weights + Base Model + Dataset Version + Code Version + Config + Environment + Evaluation

要能回答：Base Model 是谁？数据是哪版？代码哪个 commit？LR / Batch / Epoch / Seed / LoRA 参数？Best Checkpoint？Threshold 怎么定？Gold Set 哪版？

核心心智模型 ①：权重文件只是模型资产的一部分。

可复现模型必须把“产生它的条件”一起保存。

三、Dataset Version 与 Dataset Card

10,000 条数据今天修 300 个标签、明天增加 1,500 个 Hard Negative，就已经不是同一数据集。不要原地偷偷修改：

procurement_dataset_v0.1 → v0.2 → v0.3

Dataset Card 至少记录

Dataset ID / 创建日期 / 样本数身份与规模
来源、时间范围、地区范围经验边界
任务与标签 Schema监督目标
正负比例 / Hard Examples训练分布
去重方式 / 标注手册版本质量控制
已知缺陷 / Split 方式使用边界和评测可靠性

四、Label Schema 与 Annotation Guideline 也必须版本化

标签从二分类升级为 0/1/2/3 风险等级，或增加 conditional_review，实际上改变了任务定义。专家标注手册从“一律高风险”改成“结合履约必要性判断”也会造成 Label Drift。

label_schema_v1 / v2 guideline_v1.0 / v1.1
核心心智模型 ②：所有会影响结果的东西都应该被版本化。

Data、Label、Code、Config、Evaluation Set、Prompt、Retriever 都可能改变最终结果。

五、Code Version 与 Evaluation Code

训练代码进入 Git，每个 Experiment 固定 commit。Tokenizer、Padding、Loss、Data Loader、Prompt Template、Metric 计算任何一个改动都可能改变结果。

experiment.code_version = git commit abc123
高风险陷阱

V0.2 Recall 从 88% 涨到 94%，后来发现 Recall 计算代码有 Bug。Evaluation Code 本身也必须进入版本控制和自动测试。

六、Training Config：把“这次训练用什么”从代码里拿出来

experiment_id: EXP-0001
base_model: model_x
dataset_version: qualification_v0.3
learning_rate: 2e-5
num_epochs: 3
per_device_batch_size: 2
gradient_accumulation_steps: 16
optimizer: adamw
weight_decay: 0.01
warmup_ratio: 0.05
seed: 42

Code 负责“怎么训练”，Config 负责“这次具体怎么训练”。同一套代码 + 不同 Config = 不同 Experiment；这让控制实验变得清晰。

Result = f(Code, Data, Config, Environment)

七、Random Seed 与结果方差：单次最高分不是稳定能力

训练包含初始化、Shuffle、Dropout、采样、Batch 顺序等随机性。Seed 可以提高可复现性，但不保证跨 GPU/CUDA/PyTorch 完全逐位一致。

更成熟的结果表达：F1 = 0.884 ± 0.004（多 Seed）

如果 Model A=88.3，B=88.5，而不同 Seed 波动就有 ±0.8，那么不能轻易宣布 B“明显更强”。

核心心智模型 ③：训练结果应理解为随机变量，而不是一个神圣的单点数字。

重要实验应关注均值、方差和跨 Seed 稳定性。

八、Environment Version 与 Docker：代码一样不代表运行环境一样

至少记录 Python、PyTorch、Transformers、CUDA、Driver、GPU 型号。保存 requirements.txt / environment.yml；团队与服务器阶段通常进一步使用 Docker。

Reproducibility ≠ 每一位小数完全一致；目标是相同条件下结果稳定落在可解释范围。

九、Checkpoint：不仅为了“断点续训”，还为了选择真正最佳模型

checkpoint-500 / 1000 / 1500… 可以恢复训练，也可以按 Validation 选 Best Checkpoint，而不是默认使用最后一轮。

CheckpointVal F1
10000.81
20000.86
30000.89
40000.87

完整恢复往往还要保存 Optimizer State、LR Scheduler、Global Step、Random State，否则恢复后的 AdamW 相当于部分“失忆”。

十、Experiment Tracking：训练日志是证据，不是调试垃圾

当有 100 次实验时，exp_final2 这种目录命名会变成灾难。一个实验应记录输入、训练参数、训练曲线、结果、Best Checkpoint、Error Analysis 与备注。

常用工具

TensorBoard、MLflow、Weights & Biases，本质都是 Parameters + Metrics + Artifacts + Comparison。

为什么保留曲线

两个模型最终 F1 一样，但一个训练稳定、一个剧烈振荡，工程可信度完全不同。

核心心智模型 ④：训练日志是你得出模型结论的科学证据链。

没有日志，只能说“好像这个模型不错”；有日志，才能解释为什么选择它。

十一、Model Registry：每个可上线模型都应该有身份证与生命周期

实验可以有很多 checkpoint，但生产系统需要知道哪个是 Candidate / Staging / Production / Archived。

ProcurementML-Qualification-v0.3
Status: Production Candidate
Dataset: qualification_v1.4
Experiment: EXP-0042
Recall: 94.1%
Precision: 84.7%
High-Risk Recall: 97.8%
Known Limitation: 医疗复杂边界案例较弱

政府采购具有合规、审计和可追溯需求，因此未来还要关联法规库版本、Prompt、Retriever、Parser 和用户操作记录。

核心心智模型 ⑤：专业模型必须可追溯，而不仅是“有效”。

Who / What Data / What Model / What Version / What Rule / What Evidence / When，都应该能回溯。

十三、Artifact 与推荐项目目录

Artifact 是一次实验中必须保留的重要产物：dataset、config、model.safetensors、tokenizer、metrics.json、error_analysis.csv 等。

procurement_ml/
├── data/{raw,cleaned,labeled,versions}
├── configs/exp001.yaml
├── src/{data,training,evaluation}
├── experiments/EXP001/{metrics.json,training.log,error_analysis.csv}
├── checkpoints/
├── models/
├── evaluation/gold_v1/
└── README.md

发布后的 Dataset/Gold Set/Model Artifact 尽量不可原地修改；有变更就发布新版本，保持 Immutability。

十四、Gold Set、Hidden Test 与测试污染控制

Gold Test 一旦建立就冻结；如果团队每天针对它刷错题再训练，久而久之它会被间接污染。

Train → Validation → Dev Test → Gold Set → Hidden Challenge Set

开发人员可以频繁看 Dev；正式版本发布才跑 Gold；重大评审保留 Hidden Challenge，避免团队“无意识对刷题”。

十五、Quality Gate 与 Regression Test：新版本不能修 A 坏 B

示例门禁：High-Risk Recall ≥ 98%, Overall Recall ≥ 92%, Precision ≥ 82%, 且核心 Slice 无严重回归

V0.4 总体变好，但评分标准 Recall 从 91% 掉到 70%，就不能因为总分上涨直接上线。资格、技术参数、评分、商务、跨地区、长文本、Hard Negative 等都要做回归测试。

十六、Model Card：模型能力边界也必须被写下来

Model Card 示例

Purpose：供应商资格条件辅助风险筛查。
Training Dataset：qualification_dataset_v1.4。
Evaluation：GoldSet v1.2。
Strengths：注册资本、本地限制、成立年限。
Weaknesses：医疗复杂技术关联问题。
Out of Scope：最终法律结论、自动裁决。
Recommended Use：AI 初筛 + 专家复核。

“已知限制”不是缺点说明，而是专业模型治理的必要部分。

十八、第 9 阶段的 5 个专家核心心智模型

① 模型是完整训练状态

权重文件本身不足以定义一个模型。

② 一切影响结果的东西都版本化

Data、Label、Code、Config、Eval 都必须追踪。

③ 结果具有随机性

单次最高分不等于稳定能力，要看 Seed 与方差。

④ 训练日志是证据链

Experiment Tracking 是科学研发的一部分。

⑤ 专业模型必须可追溯

能从生产模型追到数据、代码、实验与规则。

一个不能复现的模型结果，很难称为真正掌握了这个模型。
