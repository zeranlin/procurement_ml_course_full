第一课 · 第 5 阶段：真正的训练过程怎么运转

Batch、Step、Epoch、Learning Rate、AdamW、Gradient Accumulation

BatchStepEpochLearning RateAdamWGradient Accumulation

一、从 10 万条政府采购数据开始：GPU 并不是一次把全部数据吞进去

假设训练集：

D = {(x₁,y₁), …, (x₁₀₀₀₀₀,y₁₀₀₀₀)}

显存有限，所以训练通常不会一次把 10 万条样本全部送入 GPU。真实主线：

Dataset → Mini-batch → Forward → Loss → Backward → Gradient → Optimizer Step → 下一批 → Epoch

二、Batch / Mini-batch：一次给模型多少样本？

假设 Batch Size=32：每次 GPU 同时处理 32 条政府采购样本。

两个极端

Batch Size=1

每看一个样本更新一次，梯度噪声很大，更新很频繁。

Full Batch

一次用全部 10 万样本算梯度，稳定但显存和计算代价巨大。

现代深度学习通常选择 Mini-batch：在效率与梯度稳定性之间取得平衡。

Batch = 局部民意调查。

我们真正想知道整个数据集希望参数往哪里走，但每次只抽一小批样本估计方向。

一个 Batch 里发生什么？

4 个案例 → Forward → 得到 p₁,p₂,p₃,p₄
→ 每个样本 Loss
→ 取 Batch 平均 Loss
→ Backward 计算所有可训练参数的 Gradient

三、Step 与 Epoch：参数真正更新了多少次？

Optimizer Step：完成一次参数更新。Epoch：模型完整看完一次训练集。

Steps per Epoch ≈ N / Effective Batch Size

例如 100,000 样本，Batch=100：

100000 / 100 = 1000 steps per epoch

训练 5 Epoch，大约 5000 次更新。

Epoch 不是能力分数。

多看几遍数据可能强化规律，也可能从“学习”走向“记忆”。最终仍要看 Validation。

四、Learning Rate：每一步到底走多远？

θ(new) = θ(old) - η · ∇θL
  • LR 太大：在最优点两侧来回跳，Loss 震荡甚至发散。
  • LR 太小：Loss 缓慢下降，训练结束时还没有学充分。
  • LR 合适：长期稳定下降并逐渐收敛。

Learning Rate Schedule / Warmup

现代训练常在开头用较小 LR 做 Warmup，随后提高，再在中后期逐步降低：

训练初期：谨慎进入稳定区域
中期：较有效率地学习大方向
后期：减小步长，精细调整

Parameter 是模型训练出来的权重；Learning Rate、Batch Size、Epoch、Weight Decay、LoRA Rank 等属于 Hyperparameter，由训练者设置。

五、SGD、Momentum、Adam、AdamW：Gradient 只是方向，Optimizer 才是“怎么走”

SGD

θ(t+1)=θ(t)-η·g(t)

当前 mini-batch 梯度指哪里，就往反方向更新。

Momentum

保留历史运动趋势，不因为单个 Batch 的偶然噪声就彻底改变方向。

Adam

综合梯度历史与自适应步长，让不同参数可以有不同“学习速度”。

AdamW

在 Transformer / LLM 训练中非常常见，可以直觉理解成 Adam + 更合理的 Weight Decay 处理。

Gradient = 坡度；Optimizer = 下山策略；Learning Rate = 步长；Batch = 用多少样本估计坡度。

六、Gradient Accumulation：显存只能放 2 个样本，怎样得到更大的 Effective Batch？

假设单卡一次只能放 4 个样本，但希望 Effective Batch=32：

Micro-batch 1：4个 → 计算梯度，不更新
Micro-batch 2：4个 → 累积
...
Micro-batch 8：4个 → 累积完成
→ 做 1 次 Optimizer Step
Effective Batch = Per-device Batch × GPU 数量 × Gradient Accumulation

例如 4 张 GPU × 每卡 2 × 累积 8：

Effective Batch = 2 × 4 × 8 = 64

所以读训练配置时不能只看 per_device_train_batch_size，要看 Effective Batch。

七、Shuffle 与 Split 是两件事

训练集内部通常会 Shuffle，避免数据顺序造成连续偏置。例如原始数据若按“资格 → 技术 → 评分”成块排列，不打乱时模型会在一段时间里被单一任务连续推动。

但：

先正确做 Project/Time Split → 再在 Train 内部 Shuffle
不要为了 Shuffle 破坏隔离。

Train / Validation / Test 的项目、时间、关联案例隔离优先级高于随机性。

九、文本模型还要看 Tokens per Batch，而不只是 Samples per Batch

政府采购文档长度差异巨大：

采购公告：短
采购需求：中等
招标文件：几十页
投标文件：几百页

32 个短问答和 2 份长招标文件的显存/算力需求可能完全不同。Transformer 的计算成本与 Sequence Length 高度相关，因此大模型训练还要关心：

Context Length / Tokens per Batch / Packing / Chunking

GPU 的主要任务不是“存知识”，而是高吞吐地执行海量矩阵乘法。知识最终体现为训练后的参数值。

十、本阶段 5 个专家核心心智模型

  1. Batch 是数据分布的局部估计：每批梯度只是总体规律的带噪声估计。
  2. Epoch 是训练深度，不是能力分数：越多可能越过拟合。
  3. Gradient ≠ Optimizer：方向、策略、步长必须分开理解。
  4. Training 是随机优化过程：有波动正常，看长期趋势与 Validation。
  5. Training 必须被监控：Loss、Val、Gradient、LR、吞吐都要看。

十一、把一次真实训练流水线完整跑在脑子里

假设：

训练样本：100,000
GPU：4 张
Per-device batch：2
Gradient accumulation：8
Epoch：3
Effective Batch = 2×4×8 = 64 Steps/Epoch ≈ 100000/64 ≈ 1563 3 Epoch ≈ 4689 Optimizer Steps

真实循环：

加载数据 → Tokenize → 送 GPU
→ Forward → Loss → Backward
→ 累积梯度（8 次）
→ Optimizer Step → Scheduler 更新
→ 下一批
→ 约 1563 次更新完成 Epoch 1
→ Validation
→ Shuffle Train
→ Epoch 2 / 3
→ 最终 Test

十二、深化理解：训练工程里几个最容易混淆的细节

1. 小 Batch 和大 Batch 都有代价

小 Batch
  • 显存低
  • 更新频繁
  • 梯度噪声更大
  • 有时泛化较好
  • GPU 利用率可能不足
大 Batch
  • 梯度更稳定
  • GPU 并行效率好
  • 显存需求高
  • 每 Epoch 更新次数更少
  • 超大 Batch 往往需要配套调整 LR

2. Optimizer Step ≠ Micro-batch 数量

如果 micro-batch=2，gradient_accumulation=16，Forward/Backward 做 16 轮后参数才真正更新一次。所以日志里的“Step”必须确认指的是 DataLoader step 还是 Optimizer step。

4. 为什么文本长度会让同一个 Batch Size 成本完全不同？

样本 A 100 tokens、样本 B 8,000 tokens，即使 Samples per Batch 都是 2，显存和算力需求也差很多。政府采购完整招标文件很长，因此后面一定会学习 Chunking、Packing、Context Length 和 Long Context。

现在你看到一份 Trainer 配置，应该开始能在脑子里“看到 GPU 正在如何一批批训练”。

6. Training Dashboard 的专家阅读顺序

  1. Train Loss 是否长期下降？
  2. Validation Loss 是否同向改善，何时开始分叉？
  3. Learning Rate 当前处于 Warmup、峰值还是衰减？
  4. Gradient Norm 是否异常？
  5. 吞吐率是否突然下降？
  6. GPU 显存/利用率是否合理？
