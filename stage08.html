第一课 · 第 8 阶段：完整机器学习实验：Experiment 001

把前七阶段的知识第一次连接成一个真正可以执行、评估、诊断和迭代的 ProcurementML 实验。

Experiment DesignBaselineSuccess CriteriaError AnalysisControlled Experiment

一、第 8 阶段总地图：第一次把前七阶段装成一台机器

目标：完整设计第一个政府采购机器学习实验——ProcurementML Experiment 001。
Problem → Hypothesis → Dataset → Baseline → Train → Evaluate → Error Analysis → Next Experiment

前七阶段学的是零件：X/Y、Loss、Gradient、Batch、Precision/Recall、Distribution、OOD、Diagnosis。第八阶段第一次把这些零件连接成一个可执行实验。

科学问题

不是“训练看看效果怎么样”，而是“提出一个可以被证伪的假设”。

工程目标

让每次训练都回答一个清晰问题，并留下可复用证据。

二、定义 Experiment 001：先做一个足够小、足够清晰的任务

第一版不要定义成“训练一个政府采购大模型”。范围太大，失败时无法定位。Experiment 001 只做：

判断政府采购文件中的供应商资格条件，是否存在潜在不合理限制风险。

它适合作为第一个实验，因为输入和标签相对清楚、业务价值明确、可获得专家标签、能计算 Precision / Recall / F1，并能向更复杂任务扩展。

原则：One Experiment, One Main Question。一次实验尽量回答一个核心问题。

三、定义 X 与 Y：实验能否被测量，取决于问题定义

1. X：模型究竟可以看到什么？

Experiment 001-A: X = 单条资格条件文本
Experiment 001-B: X = [资格条件, 采购标的, 项目类型, 上下文]

这样可以把“加入上下文是否真正提升泛化”变成下一轮可验证假设，而不是凭直觉决定。

2. Y：第一版故意保持简单

Y = 1（潜在不合理限制风险） / 0（未发现明显风险）

未来可以升级为风险类型、严重程度、法律依据、理由与建议，但第一版先把“能否识别资格条件风险”测清楚。

四、假设驱动研发：把“大模型项目”拆成一串可验证的小实验

核心心智模型 ①：模型研发不是一个“大项目”，而是一串可证伪的小实验。

每次实验只改变少数关键变量，并提前写清楚预期。

  1. EXP001：高质量专家标签能否让文本分类器明显超过关键词规则？
  2. EXP002：增加上下文能否降低漏报？
  3. EXP003：加入 Hard Negative 能否减少误报？
  4. EXP004：7B 与 14B 的增益是否值得额外成本？
  5. EXP005：RAG 是否显著提高法规依据准确率？

五、数据 Schema：今天多记录一个字段，未来就多一种诊断能力

{
  "sample_id": "xxx",
  "project_id": "xxx",
  "text": "供应商注册资本不得低于5000万元",
  "label": 1,
  "risk_type": "qualification_condition",
  "project_category": "service",
  "industry": "IT",
  "region": "某省",
  "case_date": "2026-01-15",
  "difficulty": "normal",
  "source_type": "tender_document",
  "expert_id": "expert_x",
  "label_confidence": 0.95
}
字段未来用途
project_id项目级切分，防止 Project Leakage
industry / categorySlice Evaluation 与跨领域泛化
case_date / regionTime Split、地区分布与 Concept Drift
difficultyHard Positive / Hard Negative 分析
expert_confidence标签不确定性与专家分歧管理
Data Schema = Future Evaluation Infrastructure

六、样本组成：不要让爬虫替你决定模型的世界

假设第一批有 10,000 条专家标注数据，可以主动设计分布，而不是只追求“正负各一半”。

样本类型示例数量作用
明显风险2,500学习基础模式
普通风险1,500覆盖真实常见风险
普通正常2,500建立正常分布
Hard Negative1,500打掉关键词捷径和误报
Hard Positive1,000训练“看起来正常但有风险”的边界
边界案例1,000训练不确定性和上下文依赖

具体比例不是标准答案。关键是知道每类样本为什么存在，以及它想修复什么错误。

七、数据切分：Test Set 不是“剩下的数据”，而是未来世界的模拟器

Train 8000 / Validation 1000 / Test 1000

但不能按条款随机切。政府采购数据至少要按 Project ID 隔离：同一项目的招标文件、更正、质疑答复、投诉决定不能跨集合。

进一步的真实部署模拟

时间外测试

用历史年份训练、更新年份验证/测试，模拟 Past → Future。

Challenge Set

专门保留新行业、新地区、Hard Example、同义改写和特殊案例。

核心心智模型 ②：Test Set 的任务是模拟部署，不是为了凑出一个 80/10/10。

线上面对新项目就按项目隔离；面对未来年份就做时间隔离；准备全国部署就要做跨地区评估。

八、Baseline：先问最简单的方法能做到多少

Baseline方法意义
0永远预测无风险暴露类别不平衡；风险 Recall=0
1关键词规则：注册资本、本地注册、成立年限等建立最低可解释业务基线
2TF-IDF + Logistic Regression验证“简单文本模型”已经能做到多少

如果一个 7B 模型 F1=0.82，而 TF-IDF 已经 0.81，就必须问：几十倍计算成本换来的增益值不值。

核心心智模型 ③：模型价值来自相对提升，不来自漂亮的绝对分数。

真正要看 Improvement over Baseline，同时衡量成本、延迟和复杂度。

九、指标与成功条件：在看到结果之前就写清楚“什么算成功”

这是风险筛查，所以漏报通常比误报更危险。可以把 Recall 设为主指标，Precision/F1/F2 为辅。

示例成功条件：Recall ≥ 90% 且 Precision ≥ 80% 且 High-Risk Recall ≥ 95%

还要对 Hard Negative、行业、风险类型等 Slice 定义最低标准，而不只是总体分数。

核心心智模型 ④：Success Criteria 必须预先定义。

否则训练后很容易只挑最好看的 Accuracy 宣布成功，形成 Metric Gaming / Cherry Picking。

十、选择模型与训练：复杂度逐级增加，先验证任务再烧 GPU

Rule Baseline → Logistic Regression → Small Transformer → 7B LLM → 14B LLM

每增加一层复杂度都问：“它是否带来了足够、稳定、可复现的增益？”

一个简单训练量计算

Train=8000, Batch=32 → 250 steps/epoch; 5 epochs → 最多 1250 optimizer steps

训练中至少记录 Train Loss、Validation Loss、Precision、Recall、F1/F2、Learning Rate、Step/Epoch 与 Best Checkpoint。

十一、真正打开 Test：先锁定模型、阈值和超参数

例：TP=270, FN=30, FP=60, TN=640
Recall = 270 / 300 = 90%
Precision = 270 / 330 ≈ 81.8%

达到预设成功条件并不代表实验结束。下一步才进入最值钱的工作：Error Analysis。

十二、Error Analysis：把“30 个漏报”变成下一轮实验问题

Root Cause数量下一步
Hard Positive9扩充困难正样本
上下文缺失8Experiment 002 增加上下文
医疗领域知识5补数据/RAG/专项评测
Label 错误3专家复核并修正数据
新型风险3建立新类别或扩充边界

如果最大问题是上下文缺失，就提出 Hypothesis 002：“加入采购标的与上下文能显著降低 FN”。然后只改变这一个主要变量验证。

十三、Controlled Experiment：一次主要改一个变量

如果同时换模型、加数据、改 LR、改 Loss、加上下文、加 RAG，结果从 78% 到 85%，你只知道“某些东西有效”，不知道为什么。

Hypothesis → Experiment → Measurement → Conclusion → Next Hypothesis
核心心智模型 ⑤：真正的模型能力来自实验积累，而不是某一次幸运训练。

Experiment Log 也是研发资产；失败实验同样告诉你哪些假设不成立。

十四、Experiment Card：每次实验都应该有身份证

EXP-0001 示例

Question：能否仅根据资格条件文本识别潜在不合理限制？
Hypothesis：专家标注文本分类器明显超过关键词规则。
Dataset：10,000；Project-level split 8k/1k/1k。
Baseline：关键词规则 + Logistic Regression。
Primary Metric：Recall。
Success：Recall≥90%，Precision≥80%。
Result / Error Analysis / Next Experiment：训练后填写。

随着实验变多，需要记录 Model、DataVersion、CodeVersion、LearningRate、BatchSize、Epoch、Metrics、Checkpoint、Date、Notes。后续第 9 阶段会把这套体系工程化。

十六、第 8 阶段的 5 个专家核心心智模型

① 小实验模型

把大目标拆成一串可验证、可证伪的小问题。

② 测试模拟未来

Test 的设计必须匹配真实部署场景。

③ Baseline 思维

不问模型多少分，先问相比最简单方法提升多少。

④ 预注册成功标准

在看到结果之前就定义什么叫成功。

⑤ 实验积累就是知识

每一次成功和失败都要成为可复现的研发资产。

不要“训练看看效果怎么样”，而要“提出一个假设，然后设计实验验证它”。

十七、掌握标准与小练习

思维题：如果 7B F1=0.88，Logistic Regression F1=0.87，该怎么办？

不要因为 7B“更高级”就自动选它。比较最重要 Slice、稳定性、推理成本、延迟、维护复杂度和未来扩展价值；必要时保留简单模型作为生产方案或强 Baseline。
