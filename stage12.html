第一课 · 第 12 阶段：因果、反事实与稳定泛化

第一课收官：理解相关性、混杂、干预、反事实、选择偏差和跨环境稳定规律，判断模型究竟是在“理解机制”还是“背训练世界”。

CausalityConfounderCounterfactualMinimal PairInvariant PatternDomain Generalization

一、第 12 阶段总地图：模型学的是“真正规律”，还是训练数据里的捷径？

第一课收官问题：换地区、换年份、换行业、换措辞以后，模型还能依据稳定业务逻辑判断吗？
Correlation → Spurious Correlation → Confounder → Causality → Intervention → Counterfactual → Invariant Pattern → Generalization

机器学习非常擅长发现相关性，但相关性不会自动告诉模型“为什么”。

二、Correlation ≠ Causation：预测有用，不等于解释正确

训练数据里“本市”经常出现在风险案例，模型可能学出 P(Risk | “本市”) 很高，于是看到“项目实施地点位于本市”也报警。

它真正学到的可能只是关键词与标签相关，而不是“为什么某种本地条件会产生竞争限制”。

核心心智模型 ①：模型最容易学习最好用的捷径，而不是最正确的业务解释。

Loss 只要求预测更准，不会自动检查规律是否具有业务因果意义。

三、Spurious Correlation：训练环境里好用，换环境就失效

代理机构 A 历史风险案例多，模型可能把机构名当高风险信号；某模板、PDF 页眉、投诉决定常见词也可能成为捷径。

Predictive Feature ≠ Causal Feature

这类特征会在同模板/同机构 Test 上带来漂亮分数，却在跨机构、跨行业部署时崩溃。

四、因果问题关注“如果主动改变 X，会发生什么？”

普通监督学习主要拟合 P(Y|X)。因果问题进一步问：如果人为把某个条件设置成另一种状态，Y 会怎样变化？通常用 do(X=x) 表示干预。

观察问题

历史上设置本地服务要求的项目，投诉率是否更高？

干预问题

在其他条件相同的情况下，如果取消本地注册要求，风险是否会下降？

五、Confounder：第三个变量可能同时解释 X 和 Y

项目复杂度
   ↙        ↘
本地服务要求   质疑/投诉概率

复杂项目可能更需要现场服务，同时本身也更容易产生争议。于是“本地要求 ↔ 投诉”不代表“本地要求 → 投诉”。

核心心智模型 ②：看到相关性，要主动问有没有第三个变量同时解释两边。

金额、行业、项目复杂度、竞争程度、供应商数量，都可能是 Confounder。

六、从表面关键词升级到业务机制

“注册资本 → 风险”是表面模式；更稳定的链条可能是：

资格条件 → 与履约需要的关联性 → 是否造成不必要竞争限制 → 合规风险

如果模型学到的是更深层机制，那么未来条件换成成立年限、本地注册、企业规模、业绩数量，仍可能依据相同原则判断。

七、Invariant Pattern：换环境以后仍然成立的关系

北京 IT 与广东物业表面语言完全不同，但“无必要依据地排除有能力供应商会提高合规风险”可能仍然成立。

核心心智模型 ③：真正高级的泛化，是找到跨环境稳定的规律。

Stable Across Environments 通常比单一环境最高分更有价值。

泛化可以逐层升级

  1. 换一句同义表达还能认出来
  2. 换新项目还能工作
  3. 换行业还能工作
  4. 换地区、年份还能工作
  5. 表面特征改变后仍依赖稳定机制判断

八、Counterfactual Test：只改变关键条件，看模型判断是否合理变化

现实句：“供应商必须在本市注册”，Risk=0.96。反事实：“无需本市注册，但需满足现场服务要求”。如果 Risk 明显下降，说明模型可能识别了注册地限制；若仅把“本市”改写仍高风险，则可能只是关键词捷径。

其他条件尽量不变，只改变因素 X → 观察模型结果是否按业务逻辑变化

这种最小对比测试比单独 Accuracy 更能暴露模型是否理解了真正差异。

九、Minimal Pair：用几乎相同的文本训练决策边界

A：限制注册地

供应商须在本市设立分公司。→ 高风险候选

B：只要求服务能力

供应商须在本市提供现场服务，但不限制机构设立方式。→ 需结合项目必要性判断

两句话保留大量相同词汇，只改变真正关键机制。这样的 Contrastive Data 能强迫模型放弃“本市=风险”的捷径。

十、Prediction 与 Intervention Recommendation 是两类问题

“这个条款是否值得重点审查？”是预测问题；“删除这个条件是否会降低投诉风险？”、“修改评分结构是否会增加竞争性？”则更接近因果/干预问题。

核心心智模型 ④：会预测“会发生什么”，不代表知道“改什么会让结果变好”。

修改建议需要更多法规规则、专业知识、因果逻辑和专家判断，不能只靠相关性模型。

十一、Collider Bias：只研究“被投诉项目”可能制造新的虚假关系

项目风险 → 被投诉 ← 供应商维权积极程度

如果训练数据主要来自 Complaint=1 的项目，相当于只观察一个碰撞变量被固定的子集，可能人为制造项目特征与供应商特征之间的虚假联系。

这解释了为什么“只从投诉处理决定构造全部风险数据”会产生结构性偏差。

十二、Selection Bias：数据不是现实，而是现实经过采集机制后的结果

Reality → Selection Process → Dataset

大城市项目数据更完整、发生投诉的项目更容易被收集、内部专家复杂纠错案例不公开——这些都决定哪些现实会进入训练集。

核心心智模型 ⑤：做数据时必须问“为什么这条数据会出现在我的数据库里？”

还要问哪些关键样本永远不容易被观察到。

复杂案例的缺失往往不是随机的，这与 Missing Not At Random（MNAR）思想相关。

十三、如何减少模型对 Spurious Correlation 的依赖？

方法核心思想
数据多样化让同一关键词同时出现在不同标签，打破完美捷径
Contrastive Data相似 X、不同 Y，突出真正决策边界
Counterfactual Augmentation人为改变关键机制，产生反事实训练样本
多环境训练按行业/地区/年份拆 Environment，寻找稳定关系
跨域评测用从未见过的领域测试模型，检查 Domain Generalization

十四、Domain Generalization：不要只在“已见世界”刷最高分

可以使用 Leave-One-Domain-Out：Train=IT+医疗+物业，Test=教育；下一轮 Train=IT+医疗+教育，Test=物业。

同样可以做跨地区、跨年份：北京/上海/浙江训练 → 广东测试；2022–2025 训练 → 2026 测试。

Stable Across Environments > Best on One Environment

十五、Worst-Group Performance：总体 91% 可能掩盖医疗 Slice 只有 64%

SliceRecall
IT96%
物业92%
教育91%
医疗64%

如果准备跨行业部署，必须同时报告 Average + Worst Group + Cross-Domain，而不是用高频领域把总体分数抬高。

十六、Model Explanation ≠ Causal Explanation

SHAP / Attention 告诉你“模型很依赖‘本市’这个 token”，这只能解释模型为什么这样预测；它不能证明“本市”在现实中导致合规风险。

Model Explanation

模型使用了哪些特征、为什么输出这个 Score。

Domain / Causal Explanation

为什么这个条件在业务上会影响竞争性、必要性与风险。

专业系统最好两种都保留：前者用于调试和审计，后者用于专家工作。

十七、把专家经验升级成“结构化推理标签”

高质量领域数据不应永远停留在 Text → Risk。可以把专家隐含因果链显式化：

Requirement → Business Purpose → Relevance → Necessity → Competitive Effect → Risk
{
  "condition": "供应商成立满10年",
  "intended_goal": "保证履约能力",
  "causal_relevance": "weak",
  "competitive_effect": "restrictive",
  "necessity": "not_demonstrated",
  "risk": "high"
}

这种数据更有机会教模型“为什么”，而不只是“哪些词经常和风险一起出现”。

十八、第 12 阶段的 5 个专家核心心智模型

① 模型会优先学捷径

预测有效不代表业务规律正确。

② 相关性后要找混杂因素

第三个变量可能同时解释 X 和 Y。

③ 稳定规律比单环境高分重要

真正泛化依赖跨环境不变关系。

④ 预测和干预是不同问题

会识别风险，不代表知道怎么改一定降低风险。

⑤ 数据是采集机制后的现实

数据来源与选择过程本身就会制造偏差。

真正强的模型，不是把历史相关性记得最牢，而是尽可能抓住换环境以后仍然成立的规律。

十九、第一课毕业：重新定义“机器学习”

第一阶段我们把机器学习定义为“从有限样本学习 X→Y”。经过 12 个阶段，可以升级为：

利用有限、可能有偏的数据，通过优化参数学习可预测规律，并通过严格评估、诊断、实验、工程治理和反馈，努力获得能够在未知环境中稳定泛化的能力。

更高级的目标，是减少对表面相关和环境捷径的依赖，转向更稳定、更有业务意义的规律。

第一课毕业后的 5 个总心智模型

目标函数

You get what you optimize。

数据世界

Training Data = Model's World。

泛化优先

Real Ability = Performance on Unseen World。

诊断实验

Error → Hypothesis → Experiment → Learning。

稳定规律

Stable Mechanism > Surface Correlation。

二十、第一课最终掌握标准

毕业思维题：有人说“100 万份采购文件 + 32B + Fine-tune 就能做政府采购专家 AI”，你应该追问什么？

X/Y 怎么定义？标签谁给？数据为什么会被收集？有没有项目/时间泄漏？Baseline？Recall/Precision？Hard Negative？跨行业/地区/年份？OOD？Calibration？拒答？RAG/规则？版本追踪？上线监控？模型是否依赖模板/机构/关键词捷径？这些问题已经构成第一课的完整机器学习操作系统。
