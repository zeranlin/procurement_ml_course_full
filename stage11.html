COURSE 01 · STAGE 11

第一课 · 第 11 阶段：不确定性、校准与风险控制

从“模型能不能答对”升级到“模型什么时候值得被信任”：概率校准、不确定性、OOD、选择性预测和风险驱动自动化。

CalibrationUncertaintyOODAbstentionRisk-CoverageDecision Policy

一、第 11 阶段总地图：模型什么时候值得相信？

真正危险的模型不是“经常说不知道”，而是实际上不知道，却非常自信地给出结论。
Prediction → Confidence → Calibration → Uncertainty → OOD → Abstention → Risk Control

本阶段从“怎样让模型做得更对”升级到“什么时候可以自动化、什么时候必须降级或交给专家”。

二、Score / Probability / Confidence / Truth 不是一回事

模型输出 RiskScore=0.92，首先只是当前模型下的预测分数，并不天然意味着“现实中有 92% 概率违规”。

Model Score ≠ Calibrated Real-world Probability ≠ Truth
核心心智模型 ①：答案和对答案的把握程度是两种能力。

成熟系统要考虑 Prediction + Confidence + Evidence + Uncertainty。

三、Calibration：模型说“80%”时，长期是否真的约有 80% 正确？

把所有预测在 0.8 附近的案例拿出来，如果模型校准良好，其中真正正类比例应该大致接近 80%。

Predicted 80% ≈ Empirical Positive Rate 80% → Well Calibrated

模型可以 Accuracy 很高但过度自信，也可以分类不错但总是过于保守。Accuracy ≠ Calibration。

四、两类核心不确定性：问题本身难确定，还是模型知道得不够？

Aleatoric / Information Uncertainty

现实信息本身不足或专家合理分歧，即使完美模型也需要更多事实或裁量。

Epistemic Uncertainty

模型经验不足、知识缺失或进入陌生领域；理论上可通过更多数据/知识降低。

例如核设施特殊采购，模型没经验更偏 Epistemic；某技术参数是否排他但没有市场竞争数据，则是当前证据不足导致的决策不确定性。

核心心智模型 ②：不确定时先问“缺模型能力，还是缺现实信息？”

前者补模型/数据，后者应该补上下文、市场信息、法规证据或专家调查。

五、Reliability Diagram、ECE 与 Brier Score：不确定性也可以被测量

把预测按 0.1、0.2…0.9 区间分桶，比较平均预测概率与真实发生率。例如模型在 0.9 桶实际只有 72% 正类，说明高置信区明显 Overconfident。

ECE

Expected Calibration Error：衡量各置信区间“说自己多确定”和“实际多正确”的差距。

Brier Score

平均 (p-y)²，评价概率预测质量；越小通常越好。

Precision/Recall 在某个 Threshold 下把 p=0.51 与 p=0.99 都压成同一个类别，因此完整评估要区分 Ranking、Classification、Calibration。

六、概率校准不一定要重新训练整个模型

经典方法包括 Platt Scaling、Isotonic Regression、Temperature Scaling。深度模型中 Temperature Scaling 很常见：

Softmax(z) → Softmax(z / T)

T>1 会把过于极端的 Logit 压平；分类答案可能不变，但输出概率更接近真实正确率。

核心心智模型 ③：准确性与可信度必须分别优化。

当概率参与人工分流、自动化权限和风险排序时，Calibration 不是装饰。

七、Selective Prediction：不会的时候不自动回答，是一种能力

Model A 100% 问题都答，Accuracy=85%；Model B 自动处理 70%，这部分 Accuracy=97%，剩余 30% 转专家。对专业高风险流程，B 可能更有价值。

Coverage ↓ 通常可以换取 Risk / Error ↓

这形成新的 Trade-off：Automation Coverage ↔ Reliability。

八、Risk-Based Automation：把自动化按风险分层

区域条件示例动作
Zone A高置信、非 OOD、证据充分、规则无冲突高确定性自动提示
Zone B中等置信或证据一般AI 分析 + 专家确认
Zone C低置信 / OOD / 上下文缺失不输出确定结论，转人工或补信息

九、System Confidence ≠ Model Probability

真正系统可信度可以综合模型分数、OOD、Evidence Quality、Context Completeness、Rule Consistency：

C = [C_model, C_retrieval, C_evidence, C_context, C_distribution]

即使 Model p=0.97，如果法规检索弱、OOD 高、上下文缺失，最终系统也应该谨慎，而不是展示“97% 违规”。

十、OOD 与不确定性：模型进入陌生区域时要降低自动化

可用信号包括 Embedding 与训练数据距离、最近邻相似度、输出 Entropy、多模型分歧、专门 OOD Detector、元数据是否超出支持范围。

训练分布：  ● ● ● ● ●
                    ×  ← 新项目距离很远，可能 OOD

Fluent Answer ≠ In Distribution。大模型遇到 OOD 仍可能流畅且自信地回答。

十一、多模型分歧也可以成为 Uncertainty Signal

A/B/C 都判断风险，相对稳定；A=高风险、B=无风险、C=中风险，则分歧本身应该触发专家复核。

Ensemble 或 Monte Carlo Dropout 的直觉也是多次略有差异的预测：0.91/0.93/0.90 很稳定；0.13/0.89/0.48/0.77 则高度不确定。

十二、LLM 的“置信度”不是一个维度

生成式系统可能风险分类很稳定，但法规依据不确定；也可能引用正确，但修改建议质量一般。因此可以分别评估：

Confidence_classification / Confidence_citation / Confidence_reasoning / Confidence_suggestion

这比一个笼统的“AI Confidence=92%”更符合专业工作。

十三、Conditional Prediction：输出结论成立的条件，而不是假装绝对确定

如果该业绩数量要求不能证明与项目履约复杂度存在合理关联，则存在较高不合理限制风险。

很多政府采购判断本质是 Conclusion | Assumptions。模型可以告诉用户：若市场调查显示只有少数供应商满足，风险上升；若能证明特殊履约必要性，风险下降。

核心心智模型 ④：专业 AI 不只输出答案，还应该输出“答案成立的条件”。

这会把系统从分类器升级为决策支持工具。

十四、Decision Policy 与模型必须分离

Model: X → Score
Policy: Score + Evidence + OOD + Business Cost → Action

同样 p=0.75，在“文字优化建议”场景可以直接提示，但在“自动否定供应商资格”这种高影响决策里绝不能自动执行。

可以建立纵深防御：Model → RAG Evidence → Rule Engine → Human Review，防止单一模型错误直接穿透到最终业务。

十五、自动化阶梯：权限越高，证据和人工监督要求越高

信息检索
  ↓
风险提示
  ↓
修改建议
  ↓
推荐结论
  ↓
自动执行决策
Automation Authority ↑ ⇒ Required Reliability / Evidence / Oversight ↑

政府采购高影响场景更适合 Decision Support，而不是未经人工确认的 Autonomous Final Decision。

十六、Error Budget 与 Risk-Coverage Curve

模型无法做到 Error=0，因此可以为高代价错误设 Error Budget，例如 Critical FN Rate < 1%。超过门槛则停止自动化或降级人工。

自动覆盖率自动处理错误率
100%8%
90%5%
75%2.5%
60%1.0%
40%0.3%

业务真正选择的是：“我愿意自动处理多少，换取什么可靠性？”而不是盲目追求 100% 自动化。

十七、完整系统案例：为什么 0.91 的 RiskScore 也可能必须转人工

ParserQuality0.97
DomainConfidence（医疗设备）0.55
RiskScore0.91
EvidenceConfidence0.42
OODScore0.76

虽然模型“很自信”，但领域覆盖弱、证据弱、OOD 高，最终 System Policy 应优先人工复核。

十八、Value of Information：不确定时，不只说“不知道”，还要问下一条什么信息最值钱

例如无法判断技术参数是否具有排他性时，可以主动请求：可满足品牌数量、采购需求必要性说明、替代技术方案、同类项目市场情况。

用最小信息成本，最大程度降低决策不确定性

这与 Active Learning 的思想相通：一个问“下一条标哪个样本”，另一个问“当前案例下一步补什么信息”。

十九、第 11 阶段的 5 个专家核心心智模型

① 答案与自知能力分离

做对是一种能力，知道自己可能做错是另一种能力。

② 区分不确定性的来源

问题本身不确定，与模型知识不足，不是一回事。

③ Accuracy 与 Calibration 分离

概率必须被校准后才能更可靠地参与业务决策。

④ 专业系统需要选择性预测

不可靠时拒答、补信息、转专家是一种能力。

⑤ 优化最终业务风险

目标不是最高自信或最高自动化，而是控制高代价错误。

一个可靠模型，不只是知道答案，还应该知道什么时候自己的答案不值得被完全相信。
