Underfitting、Overfitting、Bias/Variance、Train/Validation/Test

一、从“拟合”开始：模型为什么会学浅、学歪、学死？

第二阶段的核心问题：Loss 一直下降，模型就一定越来越好吗？不一定。
没学会（Underfitting） → 学到稳定规律（Good Fit） → 把训练题和噪声都记住（Overfitting）

Fit（拟合）可以理解为：模型逐渐适应训练数据中的规律。机器学习真正追求的不是 Train Loss 最低，而是真实未来数据上的错误尽可能低。

二、Underfitting：连训练数据都没学明白

例如：

数据集准确率
Train61%
Validation59%

训练集都做不好，说明模型连已有经验都没有充分利用。常见原因：

  • 输入信息不足：真实判断需要项目上下文，你却只给三个关键词特征。
  • 模型容量不足：真实关系复杂，模型表达能力太简单。
  • 优化失败：学习率、训练步数、梯度或实现有问题。
  • 标签/数据质量差：老师本身提供了大量噪声。
专家认知：模型效果差 ≠ “训练不够”。先诊断 Data、Input、Label、Capacity、Optimization，再决定是否多跑 Epoch。

三、Overfitting：训练题 100 分，新题却不会

例如：

数据集准确率
Train99.7%
Validation71%

这说明模型对训练数据极其熟悉，但对未知数据明显变差。它可能把：

  • 固定模板措辞
  • 特定代理机构名称
  • 某些项目格式
  • 偶然数字
  • 标签噪声

都当成了规律。

Shortcut Learning：捷径学习

模型不会主动追求人类心中“最深刻的业务原理”，它只会寻找能让 Loss 快速下降的可用信号。

我们希望它学：要求是否与真实履约需要合理相关、是否不必要限制竞争 模型可能偷学：出现“本市” → 风险；出现“万元” → 风险
政府采购特别容易出现捷径：

训练数据中某代理机构风险率高，模型可能学“机构名”；投诉案例里总出现“处理决定”，模型可能学未来答案提示，而不是真正审原始采购文件。

四、Bias、Variance 与 Noise：为什么“模型复杂度”必须和数据、任务匹配

High Bias：方法本身就太弱

如果模型只能检查“是否出现注册资本”这一条规则，那么无论给多少评分标准、技术参数、合同条款，它都很难学会。典型表现：

Train Error 高 + Validation Error 高 ≈ High Bias / Underfitting

High Variance：过度依赖那一批训练数据

一个很大的模型配很少的数据，可能把样本措辞、机构、项目模板全部记住：

Train 很好 + Validation 明显差 ≈ High Variance / Overfitting

经典 Bias–Variance 直觉

Expected Error ≈ Bias² + Variance + Noise

目标不是模型越复杂越好，而是：复杂到足以表达真实规律，又没有复杂到把噪声当知识记住。

Noise：标签本身也可能不确定

政府采购边界案例中，专家 A、B、C 可能给出不同意见。这时不仅存在 Model Error，还要考虑 Label Error / Label Noise。成熟数据系统必须记录：

专家意见
专家一致度
适用地区/时间
证据
置信度
是否争议案例

五、Validation 为什么重要？Early Stopping 是什么？

观察如下训练过程：

EpochTrainValidation
168%66%
275%72%
382%78%
489%81%
594%80%
697%76%

Epoch 1–4：Train 与 Validation 同时改善。Epoch 5 之后：Train 继续上升，但 Validation 开始下降。这是过拟合开始的经典信号。

Early Stopping：

当验证性能不再改善时停止训练。训练更久不等于模型更好，验证集更接近我们关心的“没见过的数据”。

Test 还要再独立，因为如果你反复根据 Validation 选模型，Validation 已经间接参与了开发。Test 是最后的正式考试。

六、Data Leakage：政府采购数据为什么不能简单随机切分？

同一个采购项目可能包含采购公告、招标文件、更正公告、中标公告、质疑答复、投诉处理决定。若按“文档”随机拆分：

招标文件 → Train
更正公告 → Validation
投诉处理决定 → Test

模型可能通过同项目线索提前“知道答案”。这叫 Data Leakage。

更合理：Project-Level Split

项目 A 的全部文件 → Train
项目 B 的全部文件 → Train
项目 C 的全部文件 → Validation
项目 D 的全部文件 → Test

如果真实使用是“过去训练，未来部署”：Time Split

2022–2024 → Train
2025 → Validation
2026 → Test
测试集必须模拟真正的部署场景，而不是追求一个看起来“标准”的随机比例。

七、泛化不是一个数字：要问“对什么变化还能泛化？”

泛化类型要回答的问题
新项目完全没见过的采购项目还能不能判断？
新时间新年度、新政策环境还能不能工作？
新地区从 A 省训练，B 省是否可靠？
新品类IT 强，到了医疗/工程是否掉点？
新措辞换一种表达还能识别同一业务本质吗？
边界案例明显案例会做，灰色复杂案例会不会？

所以“Accuracy=87%”远远不够，要知道这 87% 是在哪个分布上得到的。

八、Training Curve 与 ML Diagnosis：错误是诊断信号

欠拟合信号

Train 差，Validation 也差。

优先排查：输入信息、模型容量、数据质量、优化、训练是否充分。

过拟合信号

Train 极好，Validation 明显落后或开始变差。

优先考虑：更多多样化数据、Hard Examples、正则化、减少训练、Early Stopping、泄漏检查。

专家不会只看“Accuracy 82%”，而会把错误拆成：

漏掉风险
误报风险
风险类型错
法规依据错
事实理解错
上下文理解错
边界问题错
地区/时间规则错
幻觉

不同错误对应不同修复手段。例如法律依据总是错，可能应该加强 RAG，而不是一味扩大 SFT 数据。

九、本阶段 5 个专家核心心智模型

  1. 学不好 ≠ 训练不够：先诊断数据、输入、标签、模型容量与优化。
  2. Train 好不代表模型好：Validation/Test 才开始说明泛化。
  3. 测试必须模拟真实部署：按项目、时间、地区、品类正确隔离。
  4. 防止模型走捷径：用 Hard / Contrastive Examples 逼它学习更深层规律。
  5. 错误是信息：不要只看总分，要知道哪类错误为什么发生。
机器学习训练的目标不是把训练集做对，而是利用训练集学会解决未来问题。

十、本阶段小测与掌握标准

Train 60%，Validation 58%，你首先想到什么？

可能是欠拟合或训练/数据质量问题。重点不是立刻加 Epoch，而是诊断输入、标签、模型容量和优化。

Train 99.5%，Validation 73%，说明什么？

明显泛化差距，优先怀疑过拟合、数据泄漏、捷径学习或 Train/Val 分布不匹配。

为什么同一项目所有文档要尽量放在同一侧？

防止项目级信息泄漏，让测试真正模拟没见过的新项目。

为什么“模型判对了”仍要问“为什么判对”？

因为它可能依靠错误的表面捷径而暂时猜对，遇到分布变化就会崩。

十一、深化理解：模型“判对”也可能是错的方法

1. Hard Examples：为什么边界案例比明显案例更值钱？

如果模型只看“明显违法”和“明显正常”，它很容易学到表面关键词。更专业的数据要故意加入：

  • 看起来有限制，但存在合理履约必要性；
  • 看起来正常，却暗含不合理条件；
  • 措辞几乎相同，但答案不同；
  • 答案相同，但成立理由完全不同。

例如“本市”这个词：

样本 1：必须在本市注册 → 可能高风险
样本 2：项目履约地点位于本市 → 正常事实描述
样本 3：2小时响应但不要求提前设机构 → 需结合需求
样本 4：特殊场景确需驻场 → 可能有合理依据

这些对比能够立刻揭穿“本市=风险”的 Shortcut。

2. Decision Boundary：模型真正要画的是边界

明显风险 ● ● ● | ○ ○ ○ 明显正常 ↑ 边界附近最难

简单样本离边界远；真正决定泛化的是边界附近的 Hard Positive / Hard Negative。

3. 什么叫更稳定、更抽象的业务规律？

我们不希望模型记住“本市、注册资本、10年、品牌授权”几个词，而希望它进一步抽象为：

某项要求是否具有业务必要性 + 是否与采购标的/履约能力合理相关 + 是否造成不适当的竞争限制 + 是否有适用法规与事实支持

同一抽象原则才能迁移到成立年限、注册资本、本地机构、业绩规模、认证、人员、技术参数等不同表面形式。这也是 Representation Learning 想达到的方向。

4. Error Taxonomy：18% 的错误必须拆开

如果模型 Accuracy=82%，专家接下来不是“再训练”，而是把另外 18% 分类：

FN：漏掉风险
FP：误报正常
类型判断错
法规依据错
事实理解错
上下文理解错
边界案例错
地区规则错
时间规则错
编造依据/幻觉

若法规引用错多，方案可能是 RAG；若边界判断差，方案可能是 Hard Examples；若新品类差，是 Distribution Shift；若 Train/Val 差距大，是 Overfitting。不同病因不能吃同一种药。

5. “学生”比喻重新理解 Bias / Variance

High Bias 学生

几乎什么都不会，每套试卷都差。方法/能力本身不足。

High Variance 学生

把 1000 道原题背到满分，一换表达就不会。对训练集过度敏感。

真正专家既掌握原则，又能根据新项目灵活应用。
