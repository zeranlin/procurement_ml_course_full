第一课 · 第 3 阶段：如何正确评价一个模型

混淆矩阵、Precision、Recall、F1、Threshold 与业务代价

混淆矩阵PrecisionRecallF1Threshold 与业务代价

一、Confusion Matrix：分类模型的错误不止一种

假设测试 1000 条采购条款：真正有风险 100 条，真正无风险 900 条。模型得到：

实际有风险实际无风险
预测有风险TP = 70FP = 10
预测无风险FN = 30TN = 890
  • TP：正确抓住风险。
  • FP：误报——正常条款被报警。
  • FN：漏报——真实风险被放过。
  • TN：正确判断正常。
第一条专家认知：错误不是一种。政府采购合规审查里，FN（漏掉真正风险）的代价往往高于一次 FP（多一次人工复核）。

二、Accuracy 为什么会骗人？

Accuracy = (TP + TN) / (TP + TN + FP + FN)

代入上面的例子：

Accuracy = (70 + 890) / 1000 = 96%

听起来非常优秀，但真实 100 个风险只找到 70 个，也就是漏掉 30%。如果风险样本本来就少，Accuracy 更容易制造错觉。

类别不平衡的极端例子

假设 95% 条款正常、5% 风险。一个模型无论输入什么都回答“无风险”，Accuracy 也有 95%，但：

Recall = 0

业务上几乎没有价值。

Baseline 思维：

别人说“模型准确率 98%”时，先问正负样本比例和最简单基线是多少。Compared to what?

三、Precision：模型报警时，我能多相信它？

Precision = TP / (TP + FP)

例子里：

Precision = 70 / (70 + 10) = 87.5%

翻译成业务语言：模型每报警 100 个案例，大约 87.5 个是真正值得关注的风险。

Precision 太低会造成大量假警报，最终形成 Alarm Fatigue（警报疲劳）：专家开始忽略模型提示。

四、Recall：真实风险到底找全了多少？

Recall = TP / (TP + FN)

例子里：

Recall = 70 / (70 + 30) = 70%

这意味着 100 个真实风险只发现 70 个。

Precision

站在“模型报出来的风险”这边看：报得准不准？

Recall

站在“现实真正存在的风险”这边看：找得全不全？

政府采购第一轮筛查通常更关心 Recall

如果系统后面还有人工复核，第一道扫描宁可多报几个候选，也要尽量减少重大风险漏报。于是可以做两阶段架构：

采购文件
  ↓
高 Recall 风险扫描
  ↓
候选风险
  ↓
更强模型 + RAG + Rules + 上下文复核
  ↓
提高 Precision
  ↓
人工确认

五、Threshold：模型输出概率之后，业务怎么把它切成“报/不报”？

模型通常先输出风险分数/概率：

条款 A：0.96
条款 B：0.81
条款 C：0.63
条款 D：0.48
条款 E：0.21

如果 Threshold=0.5，则 A/B/C 报警，D/E 不报警。

降低阈值

报警更多 → Recall 往往上升 → Precision 往往下降。

提高阈值

报警更谨慎 → Precision 往往上升 → Recall 往往下降。

Threshold 本身就是业务决策，不是“默认 0.5”就天然正确。

政府采购还可以按风险类型设置不同阈值：重大合规风险阈值低一些，普通文字优化建议阈值高一些，避免提示泛滥。

六、F1 与 Fβ：怎么综合 Precision 和 Recall？

F1 = 2 × Precision × Recall / (Precision + Recall)

F1 使用调和平均，意味着 Precision 和 Recall 任何一个特别差，F1 都会明显下降。它避免“一个指标很漂亮，另一个烂得离谱”。

但 F1 默认两者同等重要。若政府采购筛查更重视 Recall，可以使用：

Fβ = (1+β²) × (Precision×Recall) / (β²×Precision + Recall) β > 1 → 更重视 Recall 例如 F₂
专家认知：不存在永远最好的指标。Metric 必须服从业务代价。

七、Macro / Micro 与 Slice Evaluation：总分会掩盖模型真正的弱点

Micro vs Macro

多分类时，大类别可能有 10,000 样本，小类别只有 500。Micro 更受大类别影响；Macro 会先分别评价各类再平均，因此更能看见长尾类别。

Slice Evaluation：按业务维度切开看

切片维度示例
风险类型资格条件 / 技术参数 / 评分标准 / 商务要求 / 程序
风险等级高 / 中 / 低
采购方式公开招标 / 磋商 / 谈判 / 询价 / 单一来源
项目类型货物 / 工程 / 服务
行业医疗 / IT / 物业 / 教育 / 工程 / 车辆
难度明显 / 普通 / 边界 / 争议

Overall Recall=92% 看似很好，但如果医疗设备 Slice 只有 61%，在医疗场景上线仍然危险。

八、机器学习本质上是在管理不同类型的错误成本

Expected Cost = C_FN × FN + C_FP × FP

如果漏掉重大风险的成本远高于多做一次复核，那么系统就应该偏向减少 FN，即提高 Recall，哪怕接受一些 FP。

还可以进一步做 Risk-Weighted Evaluation：

高风险漏报 Cost = 100
中风险漏报 Cost = 20
低风险漏报 Cost = 5

这就从“所有错误都一样”升级成 Cost-sensitive Evaluation。

业务语言比指标名称更有沟通价值

不要只说 Recall=0.94。可以说：

每 100 个真实风险，模型大约能找到 94 个；每报警 100 个案例，大约有 87 个经过专家确认确实值得关注。

九、ProcurementLM 第一套评价体系应该怎么设计？

能力层指标业务含义
风险发现Recall / High-Risk Recall真实风险有没有尽量找全
误报控制Precision报警内容是否值得专家看
分类能力Macro F1 / F2不同风险类别是否都能处理
法规依据Citation Accuracy / Valid Citation Rate依据是否真实、适用、有效
理由Expert Correctness分析逻辑是否站得住
修改建议Expert Acceptance建议是否可执行
幻觉Hallucination Rate是否编造法规、案例、事实

复杂 LLM 输出不能只用一个 Accuracy。风险判断对、法规依据错，必须分别计分。

十、本阶段 5 个专家核心心智模型

  1. 错误有不同类型：FP 与 FN 的代价要分开。
  2. Accuracy 会骗人：先看类别分布和 Baseline。
  3. 指标服从业务目标：到底优先“找得全”还是“报得准”？
  4. Threshold 是业务决策：Precision/Recall 的平衡不是纯数学问题。
  5. 平均值掩盖问题：真正要看错误分布、Slice 和高风险子集。

十一、本阶段小实验

1000 条测试数据：真实风险 200，真实无风险 800。模型正确发现风险 180，漏掉 20，误报正常 60，正确判断正常 740：

TP=180, FN=20, FP=60, TN=740 Accuracy = (180+740)/1000 = 92% Precision = 180/(180+60) = 75% Recall = 180/(180+20) = 90%

业务翻译：每 100 个真实风险约能找到 90 个；模型每报警 100 个，大约 75 个是真的风险。

十二、深化理解：从“指标”进入真正的业务决策

1. False Negative Rate：把 Recall 翻译成“每100个漏几个”

FNR = FN / (TP+FN) = 1 - Recall

Recall=92% 就等于 FNR=8%。对业务人员可以直接说：“每 100 个真实风险，大约漏 8 个。”这种表达往往比一个抽象小数更容易决定是否上线。

2. 三个模型，谁最好？没有脱离场景的答案

模型PrecisionRecall可能适用场景
A98%55%只在极确定时才自动执行的高精度动作
B83%97%第一轮风险扫描，后面有人/系统复核
C91%90%较均衡的辅助审查

所以模型优劣是 Model × Scenario 的函数，不是一个绝对排行榜。

3. Multi-class：风险类型不平衡时为什么看 Macro F1？

如果资格条件 10,000 条、合同条款 500 条，Micro 指标会被大类别主导。Macro 先给每个类别同等权重，更容易暴露“小而重要”的长尾风险类型。

4. 复杂 LLM 输出要拆成多维 Y 与多维 Metric

模型输出：
风险：是
类别：资格条件
等级：高
依据：法规A第X条
理由：……
建议：……

可能出现“风险判断对、类别对、依据错、理由部分正确、建议很好”。所以评价必须分别计算，而不能把整段回答粗暴判成“对/错”。

Y = [Risk, Type, Severity, Basis, Reason, Suggestion] Metric = [Recall, MacroF1, CitationAccuracy, ExpertScore, AcceptanceRate...]

5. 两阶段风险系统为什么是一个重要架构模式？

第一阶段用低 Threshold 做高 Recall Candidate Generation；第二阶段利用完整上下文、RAG、规则引擎、强模型提高 Precision；最终再交给人工。这和搜索、反欺诈、医学筛查等高风险系统的思路类似。

真正的机器学习系统，不是在追求 Error=0，而是在按照业务代价管理不同类型的错误。
